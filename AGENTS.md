# AGENTS.md

Instructions for AI coding assistants working in this repository. `CLAUDE.md` is a symbolic link to this file.

## Overview

A Home Assistant dashboard card (`custom:aussie-atis-card`), distributed through the Home Assistant Marketplace (2026.11 and newer) and HACS (older) as a custom repository of category `plugin`. It reads the sensors of the [Australian ATIS integration](https://github.com/BigByte76/home-assistant-aussie-atis) (`sensor.<icao>_atis*`) and draws the airport's runways, animating the runways in use.

## Commands

```bash
npm install
npm test            # Vitest unit tests for src/model.ts
npm run typecheck
npm run build       # Rollup → dist/aussie-atis-card.js (committed, because HACS and the Marketplace read it from the default branch until there's a release; CI fails if it's stale)
npm run layouts     # rebuild src/data/layouts.json from OurAirports
```

## Architecture

- `src/model.ts`: pure logic, no DOM. Runway ID normalisation, layout validation and fallback, matching ATIS runways to layout ends, wind unit conversion, and the projection (lat/lng → view box, optional rotation). Keep it DOM-free so it stays unit-testable.
- `src/map.ts`: the SVG (Lit `svg` templates). Plane animations use SMIL (`animateMotion`), chevrons and glows use CSS animations. With reduced motion, everything is drawn static.
- `src/wind.ts`: wind particles on a canvas over the SVG, in view-box units.
- `src/aussie-atis-card.ts`: the card element. Re-renders only when this airport's sensors change, and pauses animations off-screen or when the tab is hidden.
- `src/editor.ts`: the visual editor, using HA's `<ha-form>`.
- `src/data/layouts.json`: fallback layouts generated by `scripts/build-layouts.mjs`. The airport list there must match the integration's `const.py` `AIRPORTS`.

## Data contract with the integration

- Main sensor `sensor.<icao>_atis`: state is the information letter. Attributes used: `airport`, `changed_fields`, `other_info`, `arrival_runways` and `departure_runways` (lists, integration 2.1+), `runways` (layout, 2.1+).
- Without the list attributes, the card splits the `_arrival_runways` / `_departure_runways` sensor states on commas.
- Wind sensors may be converted by Home Assistant to the user's unit (often km/h), so always convert with `toKnots` using `unit_of_measurement`.
- Long text sensors have the full value in a `full_text` attribute.

## Testing

- `demo/index.html` renders the card against `demo/states.json`, which is generated from the integration's parser and test fixtures. Serve the repo root and open `/demo/`.
- Check both light and dark (`?theme=dark`) after visual changes.

## Working rules

- Don't push, publish releases, open issues or pull requests, or submit to the Marketplace/HACS default list unless the user asks in that conversation.
- Versions: `package.json` `version` and `CARD_VERSION` in `src/aussie-atis-card.ts` must match the release tag (`v` prefix optional); the release workflow checks this.
